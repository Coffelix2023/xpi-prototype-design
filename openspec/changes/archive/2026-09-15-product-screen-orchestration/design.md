## Context

当前扩展以 `(project, kind)` 组织产物，命令层直接暴露阶段和参数，`current/`、闸门、快照、预览及任务清单也按阶段聚合。详见 `proposal.md` 与 `specs/prototype-screen-orchestration/spec.md`。本设计必须继续支持本地 `file://` 预览、无构建产物、目标项目根约束、失败关闭的写入门禁和可回滚快照。

## Goals / Non-Goals

**Goals:**

- 以产品项目为容器、以页面为可操作对象，表达页面身份、实现来源、保真度和链接关系。
- 让 `/xpi-prototype-design` 成为唯一用户入口，由 Agent 通过结构化问题逐步收集目标、项目、页面范围和动作。
- 为迁移建立扫描、计划、确认、执行和验证闭环。
- 让页面级状态、预览、快照、闸门和任务进度能保护混合成熟度场景。
- 让内部模式和工具参数成为 Agent/扩展契约，而不是用户必须学习的命令语法。

**Non-Goals:**

- 不实现目标产品的生产页面、路由、后端、数据存储或业务逻辑。
- 不把迁移变成自动重构、自动视觉升级或生产代码生成。
- 不引入本地服务器、打包器、ES module 或新的运行时依赖。
- 不保证旧内部命令永久兼容；兼容策略只保护可恢复的既有产物和明确的升级路径。

## Decisions

### 1. 产品地图是规范事实来源

每个产品项目新增一个受约束的产品地图，登记稳定 page ID、名称、实现来源、保真度、可选生产 route、当前原型入口和链接声明。页面地图是页面选择、状态展示、预览和迁移映射的共同入口；不存在登记的页面不得成为页面级操作目标。

备选方案是继续从目录名和 HTML 文件名推断页面。放弃该方案，因为文件名不是稳定身份，且无法可靠表达生产页面与原型页面共存。

### 2. 实现来源与保真度分离

页面采用两个正交维度：`implementation` 表示 production、prototype、external 或 placeholder；`fidelity` 表示 none、wireframe、prototype 或 hifi。阶段目录不再代表产品整体状态，而只承载页面的相应原型产物。

备选方案是一个枚举同时表示所有状态。放弃该方案，因为组合会快速膨胀，并且“已落地”与“高保真”不是同一维度。

### 3. 统一入口，Agent 编排

`src/index.ts` 只注册 `/xpi-prototype-design` 并启动总 Skill。主菜单、产品选择、页面选择、迁移类型、影响范围和闸门文案由 Skill 使用 `ask_user_question` 或必要时的 `interview` 分步完成。扩展工具保留稳定的工程化名称和机器参数，用户不直接输入这些参数。

备选方案是在命令层继续维护多个子命令和面板。放弃该方案，因为交互语义会与页面模型同步增长，最终形成第二套工作流引擎。

### 4. 页面范围进入所有变更记录

页面级计划、任务、gate、快照和 CHANGELOG 必须记录选中的 page ID；共享导航或链接契约变更必须列出受影响页面。写入门禁只允许当前确认范围内的页面原型路径，不能只按项目/阶段宽泛放行。

### 5. 迁移采用两阶段且来源只读

迁移先扫描并产生发现结果，再生成迁移计划；用户确认映射和范围后才执行。来源路径只能读取，目标必须落在当前项目根下的产品地图和原型目录。无法确认的页面身份、链接或保真度必须进入警告/待决列表，不得静默生成 page ID。

迁移执行完成后必须运行链接检查与最小页面渲染检查，并保存迁移报告。迁移失败不得修改来源；目标侧通过迁移工作区或快照恢复。

### 6. 预览按 page ID，产品流作为组合视图

预览默认要求用户或 Agent 解析到 page ID；产品地图可提供产品流入口。禁止继续依赖“current/index.html，否则按文件名排序取第一个”作为多页面产品的语义默认。底层仍使用系统默认浏览器和本地文件预览。

### 7. 渐进迁移而非一次性重写

先增加领域契约和只读状态能力，再接入页面级操作，然后接入统一入口和迁移执行。每一阶段都保留可运行的旧产物，并通过小粒度测试验证。历史阶段产物不直接删除；无法兼容的旧布局只提示迁移，不自动搬运。

## Risks / Trade-offs

- [页面地图与既有目录暂时双轨] -> 先提供只读状态和明确迁移记录，完成页面映射后再允许页面级写入。
- [统一入口依赖 Agent 正确编排] -> 用结构化选择、范围摘要、工具参数校验和写入门禁形成四层约束。
- [旧 HTML 的页面语义不可推断] -> 迁移计划必须暴露待确认项，允许部分迁移，但不伪造完成。
- [页面级快照增加版本目录数量] -> 版本号按页面递增，CHANGELOG 显示页面范围，回滚保持局部可逆。
- [共享导航变更影响面难以估计] -> 产品地图保存链接反向引用，确认卡显示直接受影响页面；无法解析的链接使验证失败。
- [file:// 下跨页面导航受资源路径影响] -> 统一生成相对路径或明确本地入口映射，并在迁移/预览验证中检查实际可解析性。

## Migration Plan

1. 先实现产品地图、页面状态和链接契约的只读解析与测试。
2. 增加页面级目录/产物操作，同时保留旧阶段状态的只读兼容提示。
3. 将闸门、快照、预览和任务清单绑定页面范围。
4. 将命令入口收敛为单一 kickoff，更新总 Skill 的分步交互规则。
5. 增加迁移扫描、计划、确认、执行和报告；默认不覆盖已有目标文件。
6. 对历史产物执行迁移演练并保存报告，再决定是否清理兼容代码。
7. 任一阶段失败时，恢复对应快照或删除本轮新建目标；来源目录始终保持不变。

## Open Questions

无。页面状态维度、统一入口、迁移边界和产品/目标项目职责已在规划阶段确定；实现阶段只需落实具体文件格式和兼容细节，不改变上述行为契约。
