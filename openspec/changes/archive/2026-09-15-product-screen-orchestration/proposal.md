## Why

`xpi-prototype-design` 目前以 `(project, kind)` 为中心，把一个产品项目内的多个页面错误聚合为单一线框或高保真阶段，无法支持真实工作流中的混合成熟度：部分页面已落地、部分仍是线框、部分已是高保真或普通原型，同时还要保持页面身份、链接关系和交互逻辑稳定。命令也把内部模式与参数暴露给用户，增加了学习成本；旧有原型缺少受控迁移入口，容易成为规范目录之外的孤岛。

本变更现在进行，是为了在继续扩展产物和设计流程前，先建立以产品页面为核心的统一编排模型，使 Agent 能通过单一 `/xpi-prototype-design` 入口，以人类友好的分步选择引导用户，从理念、线框、高保真到落地协作，并安全接入既有原型资产。

## What Changes

- **BREAKING** 将用户入口收敛为 `/xpi-prototype-design`；用户不再需要输入 `wireframe`、`hifi`、`execute`、`update`、`archive` 或 `--*` 参数，Agent 通过结构化、逐步的人类友好选项引导流程。
- 引入产品项目级页面地图：页面拥有稳定唯一 ID、显示名称、实现来源、保真度、路由引用和页面链接关系。
- 支持同一产品内页面混合成熟度：已落地生产页面、线框、高保真、普通原型、外部页面和占位页面可以共存，页面推进不改变稳定 ID 与链接契约。
- 将状态、规划范围、预览、快照、回滚和写入闸门从阶段级收敛到页面范围；共享外壳、页面实现和生产路由保持清晰边界。
- 增加一级“迁移已有原型或线框”能力，支持只读扫描、迁移计划、用户确认、受控执行、链接检查和迁移报告；来源只读，目标限定在当前项目根的规范目录。
- 对无法安全确认的页面身份、保真度或链接关系显式标记并请求用户决定，不静默猜测或伪造迁移完成。
- 统一命令层、Agent Skill 与工具层的术语和职责：命令只负责启动统一入口，Skill 负责流程编排，工具负责状态、路径、迁移、闸门、快照和验证等机械约束。
- 保留并扩展现有安全机制：项目路径校验、失败关闭的计划闸门、版本快照、可回滚 CHANGELOG、主题事实来源、无构建与本地文件预览约束。
- 保留对既有内部流程和历史产物的受控兼容或迁移提示，避免直接丢失已有设计资产；具体兼容范围在设计阶段确定。

## Capabilities

### New Capabilities

- `prototype-screen-orchestration`: 产品项目页面地图、稳定页面身份、页面混合成熟度、页面链接契约，以及页面级状态、规划、推进、预览、快照和回滚边界。
- `prototype-migration`: 既有原型与线框的只读发现、页面与链接映射、用户确认、受控迁移、资源边界、报告和迁移后验证。
- `prototype-command-interaction`: 单一 `/xpi-prototype-design` 入口、基于用户目标的分步结构化交互、范围确认、取消语义和内部模式隐藏。

### Modified Capabilities

无。`openspec/specs/` 当前没有既有能力规范；本变更新增能力，不修改基线能力。

## Impact

- 影响 `src/index.ts` 的命令入口与交互编排、`src/contracts.ts` 的领域契约、`src/artifacts.ts` 的目录和状态操作、`src/tools.ts` 的工具参数与输出、`src/gate.ts` 的页面范围门禁，以及相关测试。
- 影响 `skills/xpi-prototype-design/SKILL.md`：从阶段中心流程改为产品页面中心流程，并增加 Agent 的人类友好分步交互规则。
- 新增迁移 Skill 及其必要的规范与资源；是否拆出独立页面契约 Skill 在 design 阶段依据规则规模决定。
- 可能引入新的页面地图、迁移记录、链接检查和页面级产物文件；不修改目标产品的生产组件、路由实现、后端业务或数据存储。
- 不新增构建步骤、打包器或不必要的运行时依赖；继续遵循 TypeScript strict、Biome 和 Vitest 验证门槛。
